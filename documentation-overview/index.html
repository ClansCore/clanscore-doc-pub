    📚 Dokumentations-Übersicht¶

    Diese Übersicht erklärt, welche Markdown-Datei für welchen Zweck verwendet wird.

    🚀 Deployment-Dokumentationen¶

    README-DEPLOYMENT.md¶

    Zweck: Schnellstart und Übersicht
    Zielgruppe: Alle Benutzer
    Inhalt: - Schnellstart-Anleitung - Übersicht über alle Services - Links zu detaillierteren Dokumentationen - Basis-Konfiguration

    Wann verwenden: Als Einstiegspunkt für neue Benutzer

    DEPLOYMENT.md¶

    Zweck: Ausführliche Deployment-Dokumentation
    Zielgruppe: Systemadministratoren, DevOps
    Inhalt: - Detaillierte Schritt-für-Schritt-Anleitung - Server-Vorbereitung - Docker & Docker Compose Setup - GitHub Actions Workflow - Reverse Proxy Konfiguration - SSL/TLS Setup - Monitoring & Logging - Troubleshooting - Erweiterte Konfiguration

    Wann verwenden: Für vollständige Server-Deployments und erweiterte Konfigurationen

    QUICK-START-SERVER.md¶

    Zweck: Server-spezifische Schnellstart-Anleitung
    Zielgruppe: Benutzer des Servers srbsci-11.ost.ch
    Inhalt: - Spezifische Anweisungen für srbsci-11.ost.ch - SSH-Verbindung - Git Clone (SSH-Key oder Personal Access Token) - Schnellstart-Deployment - Server-spezifische Tipps

    Wann verwenden: Wenn Sie auf dem spezifischen Server deployen

    🔐 Secrets & Konfiguration¶

    GITHUB-SECRETS-GUIDE.md¶

    Zweck: Vollständige Anleitung für GitHub Secrets
    Zielgruppe: Alle, die CI/CD verwenden
    Inhalt: - Was sind GitHub Secrets? - Welche Secrets müssen konfiguriert werden? - Schritt-für-Schritt Setup - SSH-Key vs. Passwort-Authentifizierung - Best Practices - Troubleshooting

    Wann verwenden: Beim Einrichten von GitHub Actions für automatisches Deployment

    GITHUB-SECRETS-CHEATSHEET.md¶

    Zweck: Schnellreferenz für GitHub Secrets
    Zielgruppe: Entwickler, die schnell nachschlagen müssen
    Inhalt: - Liste aller benötigten Secrets - Kurzbeschreibungen - Beispielwerte (ohne echte Secrets) - Quick-Reference

    Wann verwenden: Als schnelle Referenz beim Konfigurieren von Secrets

    ENV-VARIABLES-MAPPING.md¶

    Zweck: Übersicht über alle Environment-Variablen
    Zielgruppe: Entwickler, Systemadministratoren
    Inhalt: - Alle Environment-Variablen aufgelistet - Welche Service verwendet welche Variable - Beschreibung jeder Variable - Standardwerte - Erforderlich vs. Optional

    Wann verwenden: Zum Verstehen der Konfiguration und zum Troubleshooting

    🔑 SSH & Authentifizierung¶

    SSH-SETUP-PASSWORD.md¶

    Zweck: SSH-Setup mit Passwort-Authentifizierung
    Zielgruppe: Benutzer ohne SSH-Key
    Inhalt: - Passwort-basierte SSH-Authentifizierung für GitHub Actions - Setup-Anleitung - GitHub Secrets Konfiguration - Troubleshooting

    Wann verwenden: Wenn Sie keinen SSH-Key verwenden können/wollen

    GIT-CLONE-SERVER.md¶

    Zweck: Git Repository auf Server klonen
    Zielgruppe: Alle, die das Projekt auf einen Server kopieren
    Inhalt: - Warum Passwort-Auth nicht mehr funktioniert - SSH-Key Setup - Personal Access Token Setup - Schritt-für-Schritt Anleitung

    Wann verwenden: Beim ersten Klonen des Repositories auf dem Server

    💻 Lokale Entwicklung¶

    LOCAL-DEVELOPMENT.md¶

    Zweck: Lokale Entwicklungsumgebung einrichten
    Zielgruppe: Entwickler
    Inhalt: - Lokale Entwicklung ohne Docker - .env Datei Setup - npm Workspaces - Debugging - Unterschiede zu Production

    Wann verwenden: Für lokale Entwicklung und Tests ausserhalb von Docker

    LOCAL-DOCKER-SETUP.md¶

    Zweck: Lokale Docker-Umgebung einrichten
    Zielgruppe: Entwickler
    Inhalt: - Docker Compose für lokale Entwicklung - .env Datei für lokale Tests - Services starten/stoppen - Logs anzeigen - Unterschiede zu Production

    Wann verwenden: Für lokale Tests mit Docker (wie Production, aber lokal)

    LOCAL-DOCKER-TROUBLESHOOTING.md¶

    Zweck: Probleme bei lokalem Docker-Setup lösen
    Zielgruppe: Entwickler
    Inhalt: - Häufige Probleme und Lösungen - Build-Fehler - Port-Konflikte - Netzwerk-Probleme - npm Workspace-Probleme

    Wann verwenden: Wenn beim lokalen Docker-Setup Probleme auftreten

    🐳 Docker Compose Dateien¶

    docker-compose.yml¶

    Zweck: Hauptkonfiguration für alle Services
    Verwendung: Standard-Deployment
    Inhalt: - Alle drei Services (API, Dashboard, Discord-Bot) - MongoDB - Netzwerk-Konfiguration - Volumes - Health Checks

    Wann verwenden: Für Standard-Deployments (lokal und Production)

    docker-compose.production.yml¶

    Zweck: Production-Konfiguration mit Docker Hub Images
    Verwendung: docker-compose -f docker-compose.production.yml up -d
    Inhalt: - Verwendet vorgebaute Images von Docker Hub - Optimiert für Production - Keine lokalen Builds

    Wann verwenden: Wenn Sie vorgebaute Images verwenden möchten

    docker-compose.optimized.yml¶

    Zweck: Ressourcen-optimierte Konfiguration
    Verwendung: docker-compose -f docker-compose.yml -f docker-compose.optimized.yml up -d
    Inhalt: - CPU- und Memory-Limits - Optimierte MongoDB-Konfiguration - Für Server mit begrenzten Ressourcen

    Wann verwenden: Für Server mit begrenzten Ressourcen (z.B. 2 vCPU, 4GB RAM)

    📝 Scripts¶

    deploy.sh / deploy.ps1¶

    Zweck: Automatisiertes Deployment-Script
    Verwendung: ./deploy.sh (Linux/Mac) oder .\deploy.ps1 (Windows)
    Funktion: - Baut alle Services - Startet Services - Zeigt Status und Logs

    Wann verwenden: Für schnelles, manuelles Deployment

    setup-ssh-deployment.sh / setup-ssh-deployment.ps1¶

    Zweck: SSH-Key Setup für GitHub Actions
    Verwendung: ./setup-ssh-deployment.sh (Linux/Mac) oder .\setup-ssh-deployment.ps1 (Windows)
    Funktion: - Erstellt SSH-Key - Zeigt Anweisungen für GitHub Secrets - Testet SSH-Verbindung

    Wann verwenden: Beim ersten Einrichten von SSH-basiertem Deployment

    📂 Weitere Dateien¶

    backup/BACKUP-README.md¶

    Zweck: Backup- und Restore-Anleitung
    Inhalt: - MongoDB Backup erstellen - Backup wiederherstellen - Automatisierte Backups

    Wann verwenden: Für Datenbank-Backups

    🗺️ Navigation¶

    Neue Benutzer sollten starten mit: 1. README-DEPLOYMENT.md - Übersicht 2. QUICK-START-SERVER.md - Server-spezifische Anleitung (falls zutreffend) 3. GITHUB-SECRETS-GUIDE.md - Secrets konfigurieren

    Entwickler sollten lesen: 1. LOCAL-DEVELOPMENT.md oder LOCAL-DOCKER-SETUP.md 2. ENV-VARIABLES-MAPPING.md - Verstehen der Konfiguration

    Systemadministratoren sollten lesen: 1. DEPLOYMENT.md - Vollständige Dokumentation 2. GITHUB-SECRETS-GUIDE.md - CI/CD Setup 3. ENV-VARIABLES-MAPPING.md - Konfiguration verstehen
