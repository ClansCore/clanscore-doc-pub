    !!! 🔔 Webhooks¶

    Dokumentation der Webhook-Integration zwischen ClansCore-api und discord-bot.

    Übersicht¶

    Webhooks ermöglichen die Kommunikation zwischen der API und dem Discord Bot. Die API sendet Webhooks an den Bot, um über Änderungen zu informieren.

    Konfiguration¶

    Umgebungs-Variablen¶

    Variable Beschreibung Beispiel
    WEBHOOK_SHARED_SECRET Geheimer Schlüssel für Authentifizierung mein_geheimer_schlüssel_123
    DISCORD_BOT_WEBHOOK_URL URL des Discord Bot Webhook-Servers http://discord-bot:3001

    Setup¶

    1. Secret generieren: 

      # Generieren Sie einen sicheren Secret
openssl rand -hex 32

    2. In beiden Services setzen:

    3. clanscore-api: WEBHOOK_SHARED_SECRET
    4. discord-bot: WEBHOOK_SHARED_SECRET
    5. clanscore-api: DISCORD_BOT_WEBHOOK_URL

    Authentifizierung¶

    Alle Webhook-Requests müssen den Secret im Header enthalten:

    x-webhook-token: <WEBHOOK_SHARED_SECRET>

    Webhook-Endpunkte¶

    Base URL¶

    • Lokal: http://localhost:3001/api/notifications
    • Docker: http://discord-bot:3001/api/notifications

    Endpunkte¶

    1. Benutzer-Status-Änderung¶

    Endpoint: POST /api/notifications/user-status

    Wird aufgerufen wenn: - Eine Bewerbung akzeptiert oder abgelehnt wird - Ein Benutzer den Verein verlässt

    Request Body: 

    {
  "personId": "string",
  "discordId": "string",
  "status": "accepted" | "denied" | "left",
  "message": "string (optional)"
}

    Response: 

    {
  "success": true,
  "message": "Notification sent"
}

    2. Rollen-Änderung¶

    Endpoint: POST /api/notifications/role-changed

    Wird aufgerufen wenn: - Einem Benutzer eine Rolle hinzugefügt oder entfernt wird

    Request Body: 

    {
  "personId": "string",
  "discordId": "string",
  "roleId": "string",
  "action": "add" | "remove",
  "roleName": "string"
}

    Response: 

    {
  "success": true,
  "message": "Role updated in Discord"
}

    3. Rollen-Update¶

    Endpoint: POST /api/notifications/role-updated

    Wird aufgerufen wenn: - Eine Rolle im Dashboard aktualisiert wird (Name, Farbe, etc.)

    Request Body: 

    {
  "roleId": "string",
  "roleName": "string",
  "color": "string (optional)",
  "permissions": "string (optional)"
}

    Response: 

    {
  "success": true,
  "message": "Role updated in Discord"
}

    Implementierung¶

    In clanscore-api¶

    Die API verwendet den DiscordAdapter für Webhook-Requests:

    import { DiscordAdapter } from '../application/notifications/adapters/discord.adapter';

const adapter = new DiscordAdapter();
await adapter.notifyUserStatusChange({
  personId: '...',
  discordId: '...',
  status: 'accepted'
});

    In discord-bot¶

    Der Bot empfängt Webhooks über Express-Routes:

    // apps/discord-bot/src/web/routes/webhook.routes.ts
webhookRouter.post("/user-status", async (req, res) => {
  // Verarbeite Benutzer-Status-Änderung
});

    Fehlerbehandlung¶

    Fehlgeschlagene Requests¶

    Wenn ein Webhook-Request fehlschlägt:

    1. Logging: Der Fehler wird geloggt
    2. Retry: Aktuell keine automatischen Retries
    3. Fallback: Die API-Operation wird trotzdem durchgeführt

    Authentifizierungsfehler¶

    Wenn der x-webhook-token Header fehlt oder falsch ist:

    • Status: 401 Unauthorized
    • Response: { "error": "Invalid webhook token" }

    Testing¶

    Lokales Testen¶

    1. Beide Services starten: 

      # Terminal 1: API
cd apps/clanscore-api
npm run dev

# Terminal 2: Discord Bot
cd apps/discord-bot
npm run dev

    2. Webhook manuell testen: 

      curl -X POST http://localhost:3001/api/notifications/user-status \
  -H "Content-Type: application/json" \
  -H "x-webhook-token: <WEBHOOK_SHARED_SECRET>" \
  -d '{
    "personId": "test-id",
    "discordId": "123456789",
    "status": "accepted"
  }'

    Sicherheit¶

    Best Practices¶

    1. Starker Secret:
    2. Mindestens 32 Zeichen
    3. Zufällig generiert

    4. Nicht in Git committen

    5. HTTPS in Production:

    6. Webhooks sollten über HTTPS laufen

    7. Zertifikat-Validierung aktivieren

    8. Rate Limiting:

    9. Implementieren Sie Rate Limits für Webhook-Endpunkte
    10. Verhindern Sie Missbrauch

    Troubleshooting¶

    "Connection refused"¶

    • Prüfen Sie, ob der Discord Bot läuft
    • Prüfen Sie DISCORD_BOT_WEBHOOK_URL
    • Prüfen Sie die Netzwerk-Konnektivität (Docker Network)

    "Invalid webhook token"¶

    • Prüfen Sie, ob WEBHOOK_SHARED_SECRET in beiden Services identisch ist
    • Prüfen Sie den x-webhook-token Header

    Webhooks kommen nicht an¶

    • Prüfen Sie die Logs: docker-compose logs discord-bot
    • Prüfen Sie die Firewall-Regeln
    • Prüfen Sie die Docker-Netzwerk-Konfiguration
