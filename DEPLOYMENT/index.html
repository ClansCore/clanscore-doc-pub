    🚀 Dokumentations-Deployment¶

    Diese Anleitung erklärt, wie die Dokumentation aus dem privaten Repository in das öffentliche Repository deployed wird.

    Übersicht¶

    • Privates Repo: ClansCore/clanscore - Enthält die Quellen (Markdown-Dateien)
    • Öffentliches Repo: ClansCore/clanscore-doc-pub - Enthält die gebauten HTML-Seiten für GitHub Pages

    Setup¶

    Für Repos in derselben Organisation (Empfohlen)¶

    Wenn alle Repos in derselben Organisation sind (ClansCore), können Sie den automatischen GITHUB_TOKEN verwenden:

    ✅ Kein Setup nötig! Der Workflow verwendet automatisch GITHUB_TOKEN, der Zugriff auf alle Repos in derselben Organisation hat.

    Falls der GITHUB_TOKEN nicht funktioniert (z.B. wegen Organisation-Richtlinien), verwenden Sie einen Personal Access Token (siehe unten).

    Alternative: Personal Access Token¶

    Falls Sie einen expliziten Token verwenden möchten oder der GITHUB_TOKEN nicht funktioniert:

    1. Personal Access Token erstellen¶

    1. Gehen Sie zu: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
    2. Klicken Sie auf Generate new token (classic)
    3. Geben Sie einen Namen ein (z.B. "clanscore-doc-deploy")
    4. Wählen Sie die Scopes:
    5. ✅ repo (vollständiger Zugriff auf private Repositories)
    6. Klicken Sie auf Generate token
    7. Kopieren Sie den Token (wird nur einmal angezeigt!)

    2. Secret im privaten Repository hinzufügen¶

    1. Gehen Sie zu: ClansCore/clanscore → Settings → Secrets and variables → Actions
    2. Klicken Sie auf New repository secret
    3. Name: PUBLIC_REPO_DEPLOY_TOKEN
    4. Value: Der kopierte Personal Access Token
    5. Klicken Sie auf Add secret

    Hinweis: Wenn PUBLIC_REPO_DEPLOY_TOKEN gesetzt ist, wird dieser verwendet. Ansonsten verwendet der Workflow automatisch GITHUB_TOKEN.

    3. GitHub Pages im öffentlichen Repository aktivieren¶

    1. Gehen Sie zu: ClansCore/clanscore-doc-pub → Settings → Pages
    2. Source: Wählen Sie Deploy from a branch
    3. Branch: Wählen Sie main (oder master)
    4. Folder: / (root)
    5. Klicken Sie auf Save

    Automatisches Deployment¶

    Der Workflow .github/workflows/docs.yml wird automatisch ausgeführt, wenn:

    • Änderungen an docs/** gepusht werden
    • Änderungen an mkdocs.yml gepusht werden
    • Änderungen am Workflow selbst gepusht werden
    • Manuell via "Run workflow" ausgelöst wird

    Was passiert beim Deployment?¶

    1. ✅ Private Repository wird ausgecheckt
    2. ✅ Python und Dependencies werden installiert
    3. ✅ MkDocs baut die Dokumentation (mkdocs build)
    4. ✅ Öffentliches Repository wird ausgecheckt
    5. ✅ Gebaute Dokumentation wird ins öffentliche Repo kopiert
    6. ✅ Änderungen werden committed und gepusht
    7. ✅ GitHub Pages wird automatisch aktualisiert

    Manuelles Deployment¶

    Falls Sie die Dokumentation manuell deployen möchten:

    # 1. Dokumentation bauen
cd C:\Git\clanscore
pip install -r requirements.txt
mkdocs build

# 2. In öffentliches Repo kopieren
cd C:\Git\clanscore-doc-pub
git pull

# 3. Gebaute Seiten kopieren
xcopy /E /I /Y C:\Git\clanscore\site\* C:\Git\clanscore-doc-pub\

# 4. Committen und pushen
git add -A
git commit -m "Update documentation"
git push

    Troubleshooting¶

    "Permission denied" beim Push¶

    • Prüfen Sie, ob der PUBLIC_REPO_DEPLOY_TOKEN korrekt gesetzt ist
    • Prüfen Sie, ob der Token die repo Scope hat
    • Prüfen Sie, ob Sie Zugriff auf das öffentliche Repository haben

    Dokumentation wird nicht aktualisiert¶

    • Prüfen Sie die GitHub Actions Logs im privaten Repository
    • Prüfen Sie, ob GitHub Pages im öffentlichen Repository aktiviert ist
    • Warten Sie einige Minuten (GitHub Pages kann verzögert sein)

    "Repository not found"¶

    • Prüfen Sie, ob der Repository-Name korrekt ist: ClansCore/clanscore-doc-pub
    • Prüfen Sie, ob der Token Zugriff auf das öffentliche Repository hat

    URL¶

    Nach erfolgreichem Deployment ist die Dokumentation verfügbar unter:

    https://clanscore.github.io/clanscore-doc-pub/

    (Ersetzen Sie clanscore mit Ihrem GitHub Username/Organisation, falls anders)
